# 项目知库

部门内部使用的项目信息知识库。项目默认只有所有者可访问；所有者可将项目分享给指定成员只读查看。敏感字段加密保存，仅项目所有者能按次揭示。

## 本地 Docker 体验

准备：Docker Compose、Python 3。首次在项目根目录运行：

```powershell
python scripts/init_env.py
docker compose up --build -d
```

初始化命令会生成 `.env`。全新数据库的初始账号为 `admin`，密码为 `admin123`；已有数据库的管理员密码不会因初始化配置改变。浏览器打开 `http://127.0.0.1:8080`。前端经 Nginx 将 `/api` 反代到 Compose 网络中的 `backend:8000`；健康检查地址为 `http://127.0.0.1:8080/api/health`。数据库文件在项目的 `data/knowledge.db`，容器重建后仍保留。

顶部显示当前项目、主题切换和用户菜单。工作台左侧是功能菜单和项目树。项目行的操作菜单可新增子项目、编辑或移动项目、分享、查看项目记录、删除；也可拖动项目到另一个项目下，拖到“全部”恢复为顶级项目。编辑项目时可设置同级排序。选择父项目时，列表包含当前用户有权查看的子项目条目。主区域按分类 Tab 切换，在 Tab 旁的按钮可直接弹框新增或编辑分类；分类只维护名称和排序。筛选区提供环境、搜索和重置；新建条目在最右侧。条目可自行添加多个同名字段，并为每个字段选择是否隐藏；密码和谷歌验证码快捷字段默认隐藏。字段类型选择“表格”时，可点击首行预览设置行列数量并填写单元格，详情页显示完整表格。列表按当前页实际字段显示列，每页 10 条，操作栏提供查看、编辑、删除。首次启动且分类表为空时，Compose 会初始化需求文档、测试文档、接口文档、数据库、服务器、日志和 Nacos 分类；已有分类不会被改写。

Compose 默认把 `8080` 绑定到所有网卡，同一局域网内的同事可直接用 `http://<宿主机IP>:8080` 访问，需先在宿主机防火墙放行该端口。HTTP 为明文传输，登录密码和条目内容在网络中不加密，只建议在可信内网使用；跨网段或对外访问请按下一节配置 HTTPS。

## 部门 HTTPS 部署

将组织签发的证书放入 `certs/server.crt` 和 `certs/server.key`，调整 DNS 使域名指向宿主机，然后运行：

```powershell
docker compose -f docker-compose.yml -f docker-compose.https.yml up --build -d
```

HTTPS 模式开放 443，并把 `COOKIE_SECURE` 强制设为 `true`。80 端口仅在容器网络内用于重定向；宿主机默认仍有一个只绑定本机的 8080 端口。证书与 `.env` 不应上传仓库。

## 初次使用

1. 使用初始化时显示的 admin 凭据登录。
2. 成员在登录页“申请账号”，自行设置密码；admin 在“用户管理”核验身份并启用，也可直接新增用户。admin 无法重设已有成员密码。
3. 成员登录后在“账号安全”生成并保存一次性恢复码。忘记密码时使用恢复码自行重设。
4. admin 在项目资料的分类 Tab 旁新增或调整分类名称与排序。字段在新建条目时定义，例如“数据库”条目添加主机、端口、账号、密码；“接口文档”条目添加地址、版本。相同字段名可添加多次。密码和谷歌验证码快捷字段默认隐藏，每个字段均可手动调整；取消隐藏后，该值会以明文保存并对获分享权限的成员可见。
5. 成员创建项目、子项目与条目。项目所有者可从左侧项目操作菜单分享给其他已启用成员；共享成员只能查看非隐藏内容。分享父项目不会自动分享子项目，需要逐个授权。
6. 系统管理包括用户、角色、菜单和操作日志，各页使用可筛选、可翻页的数据列表。角色中的“项目资料”权限控制工作空间入口；项目所有权和分享关系仍决定可见的数据。停用角色会立即撤销该角色用户的页面权限，管理员角色不能停用。自定义菜单可调整名称、目标页面、排序和显示。删除用户会停用账号并保留历史记录；有项目归属的用户不能删除。

条目环境可留空，或从 `DEV 开发`、`TEST 测试`、`SIT 集成`、`UAT 验收`、`PRE 灰度/预发`、`PROD 生产` 中选择。顶部环境筛选使用同一组选项。
已有的其他环境值不会自动改写；编辑这类条目时会标记为“旧环境”，可保留原值或改选上述环境。

## 配置与安全

`.env.example` 列出所需变量。`FERNET_KEY` 是唯一的敏感字段加密密钥，`SESSION_SECRET` 用于会话令牌和恢复码的哈希；两者丢失都会影响现有数据或会话。`INITIAL_ADMIN_PASSWORD` 仅在空数据库首次启动时用于创建 admin；后续启动不会重置密码。生产访问必须使用 HTTPS。
Compose 将 `SEED_DEFAULT_CATEGORIES` 设为 `true`，只在数据库没有分类时写入上述默认分类。项目层级与排序使用独立关系表。启动时会把旧条目的分类模板字段转换为每条条目自己的字段，保留旧密文；升级前应按下文备份数据库。

条目标题、备注及未标记隐藏的字段以明文保存并可被搜索，不要把密码填入这些位置。搜索词以 POST 请求体传输，列表、详情及搜索响应不会包含隐藏值明文。所有者揭示隐藏值时记录审计事件；服务器不会记录密钥本身。

项目和条目权限由后端检查。admin 管理用户、角色、菜单、分类和系统操作日志，不能因此访问其他成员的项目。已使用的分类不能删除；条目字段由项目所有者单独维护。没有项目所有者的恢复码时，admin 无法通过应用找回其账号。

登录、恢复码验证和当前密码验证分别按账号限制为 15 分钟内最多 5 次尝试；超限返回 `429` 和 `Retry-After`。限制保存在单个后端进程内，进程重启会清空计数。敏感值解密失败会记录不含密钥内容的错误日志，并返回“无法解密”占位状态；前端不会复制该占位内容。

## 备份与升级

SQLite 使用 WAL。运行中的一致性备份应使用 SQLite backup API：

```powershell
docker compose exec backend python -m app.backup /data/knowledge.db /data/knowledge-backup.db
```

备份文件生成在宿主机 `data/`。另行安全备份 `.env` 中的 `FERNET_KEY`；只有数据库文件无法恢复敏感字段。SQLModel 的 `create_all` 只创建缺失的表，不负责未来表结构迁移，升级前先备份并执行该版本提供的升级步骤。

## 不使用 Docker 的开发启动

后端在 `backend/` 安装 `requirements.txt`，设置与 `.env.example` 对应的环境变量，并把 `DATABASE_PATH` 设为本地文件路径，然后启动：

```powershell
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

前端在 `frontend/` 执行 `npm install` 和 `npm run dev`。Vite 将 `/api` 代理到本机后端。

## 测试

在 `backend/` 执行 `python -m pytest tests -q`，在项目根目录执行 `node --test frontend/tests/tableField.test.mjs`。前端关键流程使用隔离数据库运行浏览器测试：安装 `backend/requirements.txt` 和 Python `playwright` 包，确保 `frontend/` 已执行 `npm install`，然后在项目根目录执行 `python frontend/tests/test_workflows.py`。测试默认使用本机 Chrome；若未安装 Chrome，可执行 `python -m playwright install chromium`，并设置 `KB_BROWSER_CHANNEL` 为空。需要分别指定后端 Python 时设置 `KB_BACKEND_PYTHON` 为已安装 `backend/requirements.txt` 的解释器路径。测试会自行启动和停止临时服务，不使用 `data/knowledge.db`。
